QUARK_QUEUE_FILE_ACCESS_NAME_ADD(3) Library Functions Manual QUARK_QUEUE_FILE_ACCESS_NAME_ADD(3)

NAME

quark_queue_file_access_name_add — register a file access name

SYNOPSIS

#include <quark.h>

int
quark_queue_file_access_name_add(struct quark_queue *qq, const char *name, int roles);

DESCRIPTION

Registers name, a single path component without slashes and shorter than QUARK_FILE_ACCESS_NAME_MAX, as a name of interest on a queue opened with QQ_FILE_ACCESS. roles is a bitmask of QUARK_FILE_ACCESS_NAME_LEAF, which reports opens of a file called name, and QUARK_FILE_ACCESS_NAME_PARENT, which reports opens of any file whose directory, or one of the two directories above it, is called name. Registering an existing name adds to its roles. At most QUARK_FILE_ACCESS_NAMES_MAX distinct names can be registered at once; one more fails with E2BIG. The names match the leaf and up to three source directories. A user with a list of full paths registers the leaf of each and filters the resolved path in the resulting quark_file_access itself. The components are those of the file on its filesystem, not of the mount it was reached through: a file under a bind mount is matched against the directories it has on the underlying filesystem, and the walk stops at the root of that filesystem. A mount-point parent name does not match if it exists only in the mount path. A file bind mount can also have a different visible leaf name. A component longer than QUARK_FILE_ACCESS_NAME_MAX - 1 bytes matches a registered name equal to its first QUARK_FILE_ACCESS_NAME_MAX - 1 bytes. The ruleset of quark_queue_attr applies to file access events through their process, as to any other event: a rule on process fields, or “drop on any”, drops them. A file.path rule never matches a file access event; the names are the only filter on the file itself.

Opens by all threads of the process that called quark_queue_open() are not reported. A forked child is reported, even if it inherits the queue. The exclusion ends when the original process exits; a later process with the same PID is reported.

RETURN VALUES

Zero on success, -1 on error with errno set. An error leaves the queue usable.

ERRORS

EINVAL
The name is NULL, empty, contains a slash, or has 64 or more bytes; the roles are zero or contain unknown bits; or the queue does not have QQ_FILE_ACCESS with the eBPF backend.
E2BIG
The map already has QUARK_FILE_ACCESS_NAMES_MAX distinct names and the new name is not present.
