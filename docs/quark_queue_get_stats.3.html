QUARK_QUEUE_GET_STATS(3) Library Functions Manual QUARK_QUEUE_GET_STATS(3)

NAME

quark_queue_get_stats — fetch queue statistics

SYNOPSIS

#include <quark.h>

void
quark_queue_get_stats(struct quark_queue *qq, struct quark_queue_stats *qs);

DESCRIPTION

quark_queue_get_stats copies out all internal statistics from qq into qs. quark_queue_stats is defined as: 
struct quark_queue_stats {
	u64	insertions;
	u64	removals;
	u64	aggregations;
	u64	non_aggregations;
	u64	lost;
	u64	garbage_collections;
	u64	retained_processes;
	u64	bpf_state_lost;
	u64	bpf_metadata_lost;
	u64	bpf_retprobe_missed;
	u64	stalls;
	int	bpf_retprobe_stats_valid;
	int	backend;
};
insertions
A counter of all events that were inserted into the queue sorting/buffering structures, this is roughly 1:1 with the actual events we read from the backend.
removals
A counter of removals of the above, you can count alive items by counting the difference.
aggregations
A counter of how many events were aggregated, this is an absolute counter, meaning a FORK+EXEC+EXIT counts as 1 aggregation, which consumes 3 events.
non_aggregations
The opposite of aggregations. It is increased by one when we didn't aggregate.
lost
A counter of missed backend events. This can happen if the user didn't call quark_queue_get_event(3) fast enough or if quark simply can't handle the load, the former is way more likely. It is a state counter representing total loss, the user should compare to an old reading to know if it increased.
garbage_collections
A counter of cached objects (processes, sockets, pods and containers) that were deleted after expiring their grace time. Containers freed together with their pod are counted individually. A retained process, see retained_processes, is counted when it is freed.
retained_processes
The number of processes that exited and are kept past their grace time only because another process is related to them, with QQ_RELATIONS, see parent in quark_queue_get_event(3). Each process is related to at most four others, so this is at most four times the number of other processes in the cache.
bpf_state_lost
Discarded or rejected BPF invocation frames: bounded-depth or map exhaustion, missed-return recovery, task exit with pending state, or ambiguous metadata. Includes ignored commands used to track nesting, so it is not an exact count of lost emitted events.
bpf_metadata_lost
Operations with a failed copied-attribute read or a successful load without captured program identity. The operation event can still be delivered with the corresponding validity bit clear.
bpf_retprobe_missed
Tracefs return-probe misses, separate from ring-buffer loss. May overlap recovered frames in bpf_state_lost; do not sum these as a count of distinct missing events. Older kernels omit return-instance-pool exhaustion from tracefs profiles. These counters can undercount losses and are not proof of complete capture.
bpf_retprobe_stats_valid
Nonzero if the last tracefs miss-count refresh succeeded with BPF telemetry enabled; otherwise the miss count is unavailable or stale.
stalls
A counter of perf rings that are stalled due to corrupt records. A stalled ring is abandoned and no further events are read from it. Only meaningful on the QQ_KPROBE backend, zero on QQ_EBPF.
backend
Active queue backend, either QQ_EBPF or QQ_KPROBE.
