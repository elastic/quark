NAME

quark_event_dump — dump a quark_event to a FILE

SYNOPSIS

#include <quark.h>

int
quark_event_dump(struct quark_event *qev, FILE *file);

DESCRIPTION

quark_event_dump dumps a human readable format of the event pointed to by qev to the file specified in file.

OUTPUT EXAMPLE

->818621 (FORK+EXEC+EXIT)
  TAGS  tags=[ log ]
  COMM  comm=git
  CMDL  cmdline=[ /usr/bin/git, --no-pager, ls-tree, --name-only, -z, HEAD, --, quark_event_dump.3 ]
  PROC  ppid=5082
  PROC  uid=1000 gid=1000 suid=1000 sgid=1000 euid=1000 egid=1000
  PROC  cap_inheritable=0x0 cap_permitted=0x0 cap_effective=0x0
  PROC  cap_bset=0x1ffffffffff cap_ambient=0x0
  PROC  time_boot=1712219191035753014
  CWD   cwd=/home/haesbaert
  FILE  filename=/usr/bin/git
  EXIT  exit_code=0 exit_time=72031260061483

FORMAT

The number 818621 after the -> is the pid of the originating process. The string (FORK+EXEC+EXIT) describes what is aggregated in this specific event. The following fields contain all the data we know about pid 818621, which originates both from this event, and whatever has been learned before and is cached.

The first column of the subsequent lines is a description of the flag from where the fields in the second column originates from. For example PROC is QUARK_F_PROC and produces the fields ppid, uid, gid, suid ...

TAGS is not a flag, it lists the names of the tags that the tag blocks of the ruleset set on this event, see quark-mon(8). An event without a tag has no TAGS line.

BLOC is not a flag either. It is printed for an operation that a block of the ruleset denied, a (BLOCKED) event:

->238271 (BLOCKED)
  TAGS  tags=[ blocked ]
  BLOC  op=rename block=1 pid=238271 tid=238271 comm=mv
  BLOC  path=/etc/passwd
  BLOC  path2=/tmp/p
  COMM  comm=mv
  ...

op is what was denied: fork, exec, create, chmod, open, truncate, rename, link or unlink. It is what the kernel was asked to do, not the system call: an open that would make a file is create, and a program that opens a file for writing before it truncates it is denied at the open. block is the number of the block in the ruleset, from 0. pid, tid and comm are of the thread that tried. path is the executable for a fork and an exec, of the parent for a fork, and the file otherwise. path2 is the new path of a rename or a link. The lines after these describe the process that tried, as it is in the cache. With the NOVA backend alone that process may not be known, and only the lines above are printed.

RETURN VALUES

Zero on success, -1 in error from fwrite(3).
