NAME

quark-mon — monitor and print quark events

SYNOPSIS

quark-mon [-aBbDEeFGgHhkLMNnSsTtuv] [-C filename] [-K kubeconfig] [-l maxlength] [-m maxnodes] [-P ppid] [-r rulefile]

quark-mon -h

quark-mon -V

DESCRIPTION

The quark-mon program listens to all incoming quark(7) events and prints them to stdout, the output format used is the one in quark_event_dump(3).

The main utility is for testing and debugging quark, it's also a good introduction to the code base. quark-mon runs until a SIGINT is received.

The options are as follows:

-a
The blocks of the ruleset also deny outside of containers. By default a block denies only the operations of a process in a container. With this option it denies them for every process of the machine. A line with a container field, pod.name or container.image, still matches only in a container. Use it with care: a block on a path that the system needs can stop the machine from working until quark-mon exits.
-B
Test bypass mode, where EBPF events are passed up directly without any processing. A * is printed for each event.
-b
Attempt EBPF as the backend.
-C filename
Dumps the contents of the internal cache into filename after exit. Format is a dot file that can be compiled to a svg with: 
dot -Tsvg filename -o filename.svg
-D
Drop priviledges to nobody and chroot to /var/empty, useful to show how quark can run without priviledges.
-E
Output ECS JSON to stdout (experimental).
-e
Include proc_entry_leader and proc_entry_type in quark_events. Entry leader is how the process entered the system, it is disabled by default as it is Elastic/ECS specific.
-F
Enable file events (experimental).
-G
Enables a getpid probe, only for benchmarking, don't use this otherwise!
-g
Use minimal aggregation, fork, exec and exit will not be aggregated.
-H
Enable SHMGET events.
-h
Display this manpage.
-K kubeconfig
Enrich events with kubernetes metadata, requires quark-kube-talker. kubeconfig is the path to the kubernetes configuration, usually $HOME/.kube/config.
-k
Attempt kprobe as the backend.
-L
Enable module loading events.
-l maxlength
Maximum lenght of the quark queue, essentially how much quark is willing to buffer, refer to quark_queue_open(3) for further details.
-m maxnodes
Don't really process events, just collect maxnodes in the sorting tree and output quark_by_time.dot and quark_by_pidtime.dot. The first is events sorted by time, and the second by pid plus time. Exits after maxnodes has been reached. This is used purely for internal debugging.
-M
Run in a simple benchmark form that only counts and display stats.
-N
Enable DNS events (experimental).
-n
Attempt NOVA as the backend.
-P ppid
Display only events where parent pid is ppid.
-S
Enable socket events (experimental).
-s
Don't send the initial snapshot of existing processes.
-r rulefile
Read rules from rulefile, use - for stdin. See RULES.
-T
Enable ptrace event tracing.
-t
Don't supress thread events, this is only useful for debugging and will likely be zapped in the future.
-u
Enable executable mprotect attempt events (EBPF only). One event is emitted for every VMA that reaches the security_file_mprotect() check with effective execute permission. The event does not assert that the protection change ultimately succeeded.
-v
Increase verbosity, can be specified multiple times for more verbosity.
-V
Print version and exit.

BACKEND SELECTION

If no backend option is specified, quark-mon uses EBPF. Exactly one of -b, -k or -n may be passed, there is no fallback between backends.

RULES

A rule file has one rule per line. A rule is an action, the word on, and one or more fields, or the word any for every event:

drop on process.uid 0 process.exe /usr/bin/*
pass on any

A ‘#’ starts a comment that ends at the end of the line. A value with a blank, a ‘#’, a ‘{’ or a ‘}’ must be quoted, as in ‘"/opt/my app/*"’. A ‘\’ at the end of a line continues the rule on the next line.

The actions are:

pass
The event is delivered, and the evaluation ends.
drop
The event is dropped, unless it has a tag, see Tag blocks. The evaluation ends.
poison N
The process of the event gets the poison tag N, which the poison field matches. The process keeps it for its later events, and its children inherit it. The evaluation goes on.

All fields of a rule must match. A field without data for the event, like file.path on a process event, or a container field for a process without container metadata, does not match. The fields are:

process.pid, process.ppid, process.uid, process.gid, process.sid number
The process id, the parent process id, the user id, the group id and the session id of the process. process.pid 0 and process.ppid 0 are rejected.
process.exe path
The executable of the process.
file.path path
The path of the file of a file event.
file.exec_change
A file was created, or its permissions changed, and it is executable afterwards. This field takes no value.
event.scope container | host | unknown
See CONTAINER SCOPE.
pod.name name
The name of the Kubernetes pod of the process container.
container.image image
The image reference of the process container, exactly as Kubernetes reports it, or as given to the container API, as in “container.image docker.io/library/nginx:1.25”.
poison N
The process has the poison tag N.

process.exe, file.path, pod.name and container.image accept one ‘*’ wildcard at any position, it matches any text, including ‘/’. So “file.path /etc/*” matches every file under /etc, and “container.image */nginx:1.25” matches that image from any registry. pod.name and container.image require container metadata, from quark-kube-talker, see -K, or from the container API of the library.

Value lists

A field can take a list of values in braces. The field matches when one of the values matches:

drop on process.exe { /bin/* /usr/bin/curl } process.uid { 0 1000 }

This rule drops an event from root or uid 1000 that runs a program in /bin or curl. A list may span lines, and an empty list is an error. file.exec_change takes no list.

Tag blocks

A tag block sets a named tag on the event. It has except on lines, then on lines, one per line:

drop on event.scope { host unknown }
tag alert {
	except on file.path /tmp/*
	on file.exec_change
}
tag log {
	on file.path *
}
drop on any

A block sets its tag when no except on line matches and one on line matches. An except on line only applies to its own block, and it needs a field. In the example, on a container event, a new executable in /tmp gets the tag log, a new executable elsewhere gets alert and log, any other file event gets log, and an event without a file is dropped.

The name is log or alert, the actions of a Defend for Containers response. The ‘{’ follows the name, and the ‘}’ has a line of its own. Blocks with the same name are alternatives. No rule tests a tag, a tag is an output: quark-mon prints it, see quark_event_dump(3).

Blocks

A block denies an operation before it happens. It has except on lines, then on lines, as a tag block, and no name:

block {
	on process.exe /usr/bin/wget
}
block {
	except on file.path /etc/hostname
	except on pod.name debug-*
	on file.path /etc/*
}

A block denies an operation when no except on line matches and one on line matches. The operation then fails with EPERM. In the example no process in a container runs wget. And no process in a container changes a file under /etc, other than /etc/hostname, unless its pod has a name that starts with debug-.

The fields of a line are process.exe, file.path, pod.name and container.image. A block is about processes or about files:

  • Every on line has process.exe or file.path, and all on lines of a block have the same one. An except on line does not have the other one.
  • “process.exe *” selects every program, and “file.path *” every file.
  • A ‘*’ is only allowed at the end of a path, and a path is shorter than 250 bytes.
  • A field appears once in a line.
  • A ruleset has at most 64 blocks and 64 different lines in them.

What a line denies depends on its path field:

process.exe
An exec of the program, and a fork of a process that runs it. A new thread is not a fork. A script is denied when it is executed, not when it is given to its interpreter as an argument.
file.path
The operations that make, change or remove the file: the creation of a regular file, an open for writing, a change of its mode, a truncate, a rename from the path or to it, a hard link to the file or with the path as the new name, and an unlink. A read is not denied. An open, a change of mode and a truncate are denied for a regular file only. A directory, a symbolic link or a special file can still be made, and a directory removed. The path is the one the process sees, from its root directory.

A block denies only in a container, unless -a is given. A container is what event.scope calls one, see CONTAINER SCOPE, so without -a a process in the host or the unknown scope is not denied. event.scope is not a field of a block.

A field without data does not match, also in an except on line. So “except on pod.name debug-*” does not protect a pod before its metadata arrived, and a line with pod.name or container.image never matches a container that Kubernetes does not know. A path that can't be resolved, or is 250 bytes or longer, matches no line.

A denied operation is one event, BLOCKED, with the operation, the block and the path, see quark_event_dump(3). It did not happen, so it is no other event: a denied exec is not an exec event. The event has the tag blocked and is always delivered.

Blocks need Linux 5.17 on x86_64, other architectures are not tested, with the BPF LSM active: bpf must be in /sys/kernel/security/lsm, which the lsm= boot parameter sets. A block on file.path also needs the path hooks of the kernel, CONFIG_SECURITY_PATH. Where blocks can't work, quark-mon fails to start on a ruleset with a block.

Evaluation

The rules are evaluated from top to bottom. The first matching pass or drop rule ends the evaluation. poison rules and tag blocks don't end it, so every matching block sets its tag. After the evaluation an event is dropped when the last matching rule is a drop and the event has no tag. Every other event is delivered, also an event that no rule matched. So a drop rule before a tag block removes an event, and “drop on any” as the last rule removes every event without a tag.

A block is not part of this evaluation. It is enforced in the kernel before the operation, and the other rules see events after it. So a pass or a drop rule above a block does not stop it, and the place of a block in the file does not matter. No rule is evaluated on a denied operation.

The initial snapshot of existing processes, see -s, is not filtered by the rules.

Backends

The EBPF backend supports every rule. For a ruleset with a block it also loads the LSM programs of the NOVA backend, which only deny, and it loads nothing of NOVA for a ruleset without one. The kprobe backend does not report the cgroup of new processes, so it rejects event.scope, pod.name and container.image. It also rejects a ruleset with a block. The NOVA backend enforces blocks. Outside of a block it rejects these three fields, file.exec_change, value lists with more than one value, a field that is repeated in one rule and tag blocks. A ruleset with a block can't be used with -B.

CONTAINER SCOPE

The event.scope field puts every event in exactly one of three scopes:

container
The last component of the process cgroup is a container scope of the systemd cgroup driver, like cri-containerd-<id>.scope or crio-<id>.scope, where id is the container ID in lowercase hex. This is the kubeadm default since Kubernetes 1.22. Host units that share the prefix, like the conmon monitor in crio-conmon-<id>.scope or the service crio-wipe.service, are not containers.
host
The process cgroup is an absolute path under /init.scope, /system.slice or /user.slice, the systemd host layout, with no .. component and no component that is a container scope.
unknown
Everything else.

To keep only container events on a Kubernetes node, use:

drop on event.scope { host unknown }

The following are unknown, neither a container nor the host, so the rule above drops their events:

  • All containers on a node that uses the cgroupfs driver, like /kubepods/burstable/pod<uid>/<id>.
  • A process in a nested cgroup of a container, like cri-containerd-<id>.scope/init.scope.
  • The root cgroup /, a cgroup path relative to a cgroup namespace, like /../system.slice/foo.service, and any other layout, like /machine.slice.
  • An event without a process, or from a process with an unknown or empty cgroup.

Containers outside Kubernetes are not a supported use case. The field is only supported by the EBPF backend.

EXIT STATUS

quark-mon exits with 0 in if a SIGINT was sent, or 1 in case of error.
