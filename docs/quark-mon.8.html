NAME

quark-mon — monitor and print quark events

SYNOPSIS

quark-mon [-BbDEeFGgHhkMNnSsTtuv] [-a name] [-C filename] [-K kubeconfig] [-l maxlength] [-m maxnodes] [-P ppid] [-r rulefile]

quark-mon -h

quark-mon -V

DESCRIPTION

The quark-mon program listens to all incoming quark(7) events and prints them to stdout, the output format used is the one in quark_event_dump(3).

The main utility is for testing and debugging quark, it's also a good introduction to the code base. quark-mon runs until a SIGINT is received.

The options are as follows:

-a name
Enable file access events (EBPF backend only, experimental) and report opens of files named name. Use one path component for name. The component must contain 1 to 63 bytes and no slash. If name ends in a slash it is a directory name instead, and opens of any file up to three levels below a directory of that name are reported. This final slash does not count in the 63-byte limit. This option can be given up to 64 times.
-B
Test bypass mode, where EBPF events are passed up directly without any processing. A * is printed for each event.
-b
Attempt EBPF as the backend.
-C filename
Dumps the contents of the internal cache into filename after exit. Format is a dot file that can be compiled to a svg with: 
dot -Tsvg filename -o filename.svg
-D
Drop priviledges to nobody and chroot to /var/empty, useful to show how quark can run without priviledges.
-E
Output ECS JSON to stdout (experimental).
-e
Include proc_entry_leader and proc_entry_type in quark_events. Entry leader is how the process entered the system, it is disabled by default as it is Elastic/ECS specific.
-F
Enable file events (experimental).
-G
Enables a getpid probe, only for benchmarking, don't use this otherwise!
-g
Use minimal aggregation, fork, exec and exit will not be aggregated.
-H
Enable SHMGET events.
-h
Display this manpage.
-K kubeconfig
Enrich events with kubernetes metadata, requires quark-kube-talker. kubeconfig is the path to the kubernetes configuration, usually $HOME/.kube/config.
-k
Attempt kprobe as the backend.
-L
Enable module loading events.
-l maxlength
Maximum lenght of the quark queue, essentially how much quark is willing to buffer, refer to quark_queue_open(3) for further details.
-m maxnodes
Don't really process events, just collect maxnodes in the sorting tree and output quark_by_time.dot and quark_by_pidtime.dot. The first is events sorted by time, and the second by pid plus time. Exits after maxnodes has been reached. This is used purely for internal debugging.
-M
Run in a simple benchmark form that only counts and display stats.
-N
Enable DNS events (experimental).
-n
Attempt NOVA as the backend.
-P ppid
Display only events where parent pid is ppid.
-S
Enable socket events (experimental).
-s
Don't send the initial snapshot of existing processes.
-r rulefile
Read rules from rulefile, use - for stdin. See CONTAINER SCOPE for the “event.scope” field. The “pod.name” field matches events from a process in a container that belongs to the named Kubernetes pod. A single ‘*’ wildcard is accepted, as in “pod.name nginx-*”. The “container.image” field matches events from a process in a container whose image reference matches the given string. The image reference is compared exactly as Kubernetes reports it, or as given to the container API, as in “container.image docker.io/library/nginx:1.25”. A single ‘*’ wildcard is accepted, so “container.image */nginx:1.25” matches that image from any registry, and “container.image quay.io/*” matches every image from that registry. Both fields require container metadata, from quark-kube-talker, see -K, or from the container API of the library. An event without a process, or from a process whose container is unknown, matches neither field. Like “event.scope”, these fields are only supported by the EBPF backend.
-T
Enable ptrace event tracing.
-t
Don't supress thread events, this is only useful for debugging and will likely be zapped in the future.
-u
Enable executable mprotect attempt events (EBPF only). One event is emitted for every VMA that reaches the security_file_mprotect() check with effective execute permission. The event does not assert that the protection change ultimately succeeded.
-v
Increase verbosity, can be specified multiple times for more verbosity.
-V
Print version and exit.

BACKEND SELECTION

If no backend option is specified, quark-mon uses EBPF. Exactly one of -b, -k or -n may be passed, there is no fallback between backends.

CONTAINER SCOPE

The “event.scope container” rule field matches events from a process in a Kubernetes container. To keep only container events on a Kubernetes node, use:

pass on event.scope container
drop on any

A container is recognized only when the last component of the process cgroup is a container scope of the systemd cgroup driver, like cri-containerd-<id>.scope or crio-<id>.scope. This is the kubeadm default since Kubernetes 1.22. The following are not recognized as containers, and the rules above drop their events:

  • All containers on a node that uses the cgroupfs driver, like /kubepods/burstable/pod<uid>/<id>.
  • A process in a nested cgroup of a container, like cri-containerd-<id>.scope/init.scope.
  • An event without a process, or from a process with an unknown cgroup.

Containers outside Kubernetes are not a supported use case. The field is only supported by the EBPF backend. The kprobe backend does not report the cgroup of new processes, so it rejects the field, and so does the NOVA backend.

EXIT STATUS

quark-mon exits with 0 in if a SIGINT was sent, or 1 in case of error.
