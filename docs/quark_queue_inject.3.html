QUARK_QUEUE_INJECT(3) Library Functions Manual QUARK_QUEUE_INJECT(3)

NAME

quark_queue_inject — inject a decoded synthetic event

SYNOPSIS

#include <quark.h>

int
quark_queue_inject(struct quark_queue *qq, const struct quark_synthetic_event *event);

DESCRIPTION

quark_queue_inject copies and inserts the decoded synthetic event pointed to by event into the raw-event trees of qq. The queue must have been opened with the QQ_SYNTHETIC backend.

The synthetic backend and this function are omitted from normal builds. Build with WITH_SYNTHETIC=1 to enable them.

This interface is benchmark and test support. It enters the production event path immediately before internal raw_event_insert() and therefore exercises raw-event sorting and aggregation, process-cache updates and garbage collection, userspace rules, and quark_event construction. It does not execute probes, transport events through ring buffers, decode backend records, or evaluate BPF-side filters.

Supported event.kind values are:

QUARK_SYNTHETIC_FORK
 
QUARK_SYNTHETIC_EXEC
 
QUARK_SYNTHETIC_EXIT
 
QUARK_SYNTHETIC_SETSID
 
QUARK_SYNTHETIC_FILE_CREATE
 
QUARK_SYNTHETIC_FILE_MODIFY
 
QUARK_SYNTHETIC_FILE_DELETE
 

event.time is a required nonzero timestamp in nanoseconds since CLOCK_BOOTTIME. event.process.pid is required for every event. A fork, exec, exit or setsid additionally requires a non-empty event.process.comm, matching the backends, which always report the kernel's task->comm. An exec additionally requires a non-empty event.process.executable; a file event requires a non-empty event.file.path.

Process input includes credentials, capabilities, parent, process-group and session relationships, controlling TTY, namespaces, start and exit data, cwd, cgroup, argv, environment, comm, and executable. It applies to fork, exec, exit and setsid events only. argv and executable are recorded by an exec only, which is the only event a backend reports them on. Both are ignored on a fork, exit or setsid, so a caller may reuse one process for a whole lifecycle. A fork still reports a cmdline, inherited from its parent as it is with a backend. A file event uses just event.process.pid and the file fields; its process is resolved through the process cache, so it reports no process until an earlier event has populated the cache for that pid. This matches the backends, whose file events also carry only a pid. File input includes paths, inode, timestamps, size, mode, ownership and change mask. argv and env are NUL-delimited buffers whose final byte must be NUL. Environment input is limited by the queue's max_env attribute in the same way as decoded backend input.

All strings and buffers are copied before quark_queue_inject returns, so the caller retains ownership and may immediately reuse them. Injection is synchronous. Like the rest of a quark_queue, it is not safe to call concurrently on the same queue.

RETURN VALUES

Zero on success, -1 otherwise and errno is set.

ERRORS

[EINVAL]
The queue is not synthetic, a pointer is NULL, the event kind is unsupported, or a required field or NUL-delimited buffer is malformed.
[ENOMEM]
Memory for the copied event could not be allocated.
[EOVERFLOW]
The combined file-path storage length overflowed.
[EEXIST]
The event could not be placed in the queue. Two events may not hold the same timestamp, so an event that arrives on a taken timestamp moves to the next free one. This error means that a thousand consecutive timestamps from event.time onwards were all taken. The event is dropped.

Because a colliding event moves to the next free timestamp, the time an event reports is not always the event.time it was given. An exit reports the same value in exit_time_event and in its event time.
